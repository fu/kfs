One namespace, everything in it, live.
Like kubectl get -w on steroids — all linked up.

po what it is

kfs shows a namespace on one page that updates in place: the GitOps apps that deploy it, its deployments, replicasets, pods with CPU and memory, services, ingress routes, configmaps and secrets — and below them a change log of everything that happens there, including what happened before you started.

Select a row and everything linked to it lights up, across sections: app → deployment → replicaset → pods → secrets, configmaps, claims and volumes, and the services and ingress routes in front of them.

rs install

  1. macOS / Linux, with Homebrew

    brew install fu/tap/kfs

  2. or with Go

    go install github.com/fu/kfs@latest

  3. or a binary

    macOS, Linux and Windows builds on the releases page. Unpack it and put kfs on your PATH.

  4. run it

    kfs uses your kubeconfig, exactly like kubectl. No setup.

    kfs -n shop

Coming from k7s? brew uninstall k7s, then install kfs as above. The config now lives in ~/.config/kfs/.

svc usage

$ kfs                       # the current namespace
$ kfs -n shop               # namespace shop
$ kfs -n shop -l app=web    # only one app in it
$ kfs -n shop --once        # print the sections once and exit
